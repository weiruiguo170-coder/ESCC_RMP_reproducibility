# Source data and acquisition

The repository distributes compact deidentified derived outputs, not full raw sequencing, clinical workbooks or complete third-party libraries. Obtain source materials through the official records and preserve source-study permissions. Controlled-access resources must be accessed through their normal authorization process; no bypass is provided.

Raw-analysis scripts use `ESCC_INPUT_ROOT`, which defaults to the ignored `data/raw/` directory. Use a separate working input tree and place acquired matrices/workbooks in the relative paths named by the relevant module. Original pipeline modules expect `data/raw/<accession>/`, `data/interim/` and generated `results/` below that input root. Revision modules also name processed cohort files and source-study tables. The curated replay uses only the included catalog and does not need this input tree.

The source-data order is preprocessing → cohort-specific pilot/formal cNMF → normalized usage and matching → frozen signatures → external expression/Q → tissue and clinical models → protein and PDO analyses → domain-specific evidence synthesis. Module configurations and current seeds are in `data/metadata/`. The primary raw-paired protein calculation is `scripts/analysis/proteomics/paired_protein.py`; `global_z.py` is a distinct historical standardization/helper, not the submitted raw-paired dz definition. Exact current PDO inference is reconstructed in `scripts/replay.py` and `scripts/validation/day15.py` after raw expression scoring.

Author-proteome extraction is supplied in `scripts/analysis/proteomics/extract_author_matrix.py`. The optional author-Seurat metadata extractor is `scripts/analysis/quality/extract_author_metadata.R`; its original R version was not recorded. Source assays and optional full environments were not re-downloaded or refitted during cleanup. Successful compact replay must not be described as full raw-assay reproduction.

Published-program comparison can also be run directly from the official memberships, without refitting expression models:

```text
python scripts/analysis/revision/reference_programs.py --zhang-workbook <SupplementaryData5.xlsx> --gavish-tsv <Gavish2023_author_gene_lists.tsv> --hgnc <hgnc_complete_set.txt>
```

The Zhang source is Supplementary Data 5 (`41467_2021_25539_MOESM8_ESM.xlsx`, sheet `Genes`) of [Zhang et al.](https://doi.org/10.1038/s41467-021-25539-x). Gavish author memberships are from [the author 3CA collection](https://github.com/tiroshlab/3ca/tree/21a784103528cdf15008761f9669e2025159d6d2/ITH_hallmarks); the TSV has `cell_type`, `reference_program` and `gene` columns extracted from the official RDS with `Rscript scripts/analysis/revision/export_gavish.R <author.RDS> <memberships.tsv>`. The original R version was not recorded; this extraction was not rerun here. Frozen source identities and HGNC mapping hashes are listed in `data/metadata/reference_programs/resources.tsv`. `scripts/analysis/revision/fetch_references.py` downloads the pinned official resources, verifies their original checksums, and extracts them without retaining archives. Obtain the checksum-matched HGNC export through the official archive before regenerating comparisons. The overlap command checks all 686 results and collection/size-specific BH families against the included table. These source-list calculations were rerun successfully using the archived official resources; source memberships are not inferred from the overlap results.

Clinical source scripts read the official GSE53622/GSE53624 clinical workbooks under `01_data_raw/`, accepting either the original `.xlsx.gz` download or its decompressed `.xlsx`. PDO endpoint auditing reads `08_PDO_functional_validation/raw/paper/supplementary/42003_2025_7869_MOESM3_ESM.xlsx`. These paths are relative to `ESCC_INPUT_ROOT`; no private extraction ledger is required. Raw-analysis modules also require the upstream intermediate files named in their source. The portable workflow is the verified, self-contained entry point; source-assay modules are provided for controlled regeneration in a separately prepared input tree.

Full reference libraries remain download-only. The retained enrichment-resource table provides the Enrichr URLs, frozen library names/access dates and raw/GMT checksums for Hallmark2020, Reactome2024, GO Biological Process2026 and KEGG2026. Use `scripts/analysis/discovery/enrichment_resources.py` with the source terms, then compare the obtained hashes with the frozen metadata before reannotation. A changed download must not silently replace the frozen resource. Full study enrichment results and the measured/published-program overlap backgrounds are retained.

All repository files are ordinary text. Two larger logical tables are partitioned into ordinary TSV parts below 24 MiB, preserving every row and the exact concatenated checksum. The 124,728,960-byte parameter-grid cache exceeds [GitHub's 100-MiB ordinary-file limit](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github); its complete deterministic generator, frozen inputs, checksum and summary are supplied instead. `python scripts/evidence/grid.py` verifies exact reconstruction without writing the cache. An optional full export is for local use outside Git. No necessary data are silently replaced by an example or synthetic input.

For the second proteome, place author-derived `rna.tsv` and `protein.tsv` under `ESCC_INPUT_ROOT/second_proteome/`. The RNA table requires `Gene ID`, `Gene name` and specimen columns; the protein table requires `Protein accession`, `Gene name` and specimen columns, with the source T/P suffixes preserved. The script reads the same 14 included frozen signatures directly.
